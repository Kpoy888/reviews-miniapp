# Витрина отзывов и сертификатов

Бесплатная витрина с отзывами о работе по **ИИ-автоматизации техподдержки** и **проектированию** (Renga, nanoCAD, Revit; BIM/ТИМ, чертежи и документация), а также вкладкой **«Сертификаты и достижения»**. Сервер не нужен: страница лежит на GitHub Pages, отзывы и сертификаты хранятся в Google-таблице, фото сертификатов — на Google Диске.

Сайт открывается в любом браузере. Telegram-бот **не обязателен**: добавлять сертификаты можно после входа по паролю. Бот понадобится только если захотите открывать витрину кнопкой внутри Telegram.

Никаких платных тарифов: GitHub Pages, Google Apps Script и Google Диск в этом сценарии бесплатны.

## Что получится

- Красивая страница с двумя вкладками: **Отзывы** и **Сертификаты**.
- Услуги, средний рейтинг, фильтр по направлению, карточки отзывов и форма.
- Новые отзывы не публикуются сразу — в таблице есть столбец `approved`. Вы сами решаете, что показать.
- Вкладка сертификатов: сетка карточек с превью, названием, кем выдан, годом, необязательным описанием и ссылкой. Нажать на фото — открыть крупно. Если сертификатов ещё нет, показывается «Сертификаты скоро появятся».
- Добавлять и удалять сертификаты можете **только вы**, после входа по паролю («Вход для владельца»). У остальных вкладка только для просмотра. Пароль хранится в свойствах Google Apps Script, в коде сайта его нет.
- Если URL бэкенда ещё не указан или одобренных отзывов нет, на месте списка отзывов будет приглашение оставить первый отзыв. Форма при этом работает: без бэкенда отзыв не публикуется, вместо этого предлагается написать в Telegram. На вкладке сертификатов в этом случае тоже пустое состояние; при попытке входа будет подсказка, что сначала нужно подключить Google Apps Script.

## Состав проекта

```

  styles.css                    # оформление
```

## 1. Подпишите витрину своим именем

Откройте `config.js` и измените:

- `OWNER_NAME` — как вас представлять (вместо «Ваше имя»);
- `OWNER_TAGLINE` — короткий слоган, если хотите другой;
- `TELEGRAM_USERNAME` — необязательно, например `ivan_petrov` (без `@`), тогда в подвале появится ссылка «Написать».

Поле `APPS_SCRIPT_URL` пока оставьте пустым: сначала выложим таблицу и получим адрес.

**Не записывайте пароль в `config.js` и не публикуйте его в репозитории.** Он живёт только в свойствах скрипта Google.

## 2. Google-таблица и Apps Script

1. Создайте новую [Google-таблицу](https://sheets.new), например «Отзывы и сертификаты».
2. Меню **Расширения → Apps Script**.
3. Удалите заготовку в редакторе и вставьте содержимое файла `apps-script/Code.gs`. Сохраните проект.
4. Откройте **⚙ Настройки проекта** (иконка шестерёнки слева) → раздел **Свойства скрипта** (Script properties) и добавьте свойство:
   - `ADMIN_PASSWORD` — длинный пароль владельца. Придумайте его сами, никуда больше не вставляйте и не присылайте.
5. Выберите функцию `setup` в списке функций сверху и нажмите **Выполнить**. Google попросит разрешение:
   - выберите свой аккаунт;
   - если появится «Приложение не проверено», нажмите **Дополнительно → Перейти на страницу проекта (небезопасно)** — это ваш собственный скрипт;
   - разрешите доступ к **таблице** и к **Google Диску** (папка для фото сертификатов создаётся автоматически).
6. **Развернуть → Новое развёртывание**:
   - тип: **Веб-приложение**;
   - описание: например `reviews-v3`;
   - **Выполнять как:** Меня;
   - **У кого есть доступ:** Все.
7. Нажмите **Развернуть** и скопируйте URL вида  
   `https://script.google.com/macros/s/XXXX/exec`.
8. Вставьте этот URL в `config.js` в поле `APPS_SCRIPT_URL`.

Если вы уже публиковали предыдущую версию скрипта, после замены `Code.gs` обязательно:

1. Снова запустите `setup()` — появятся лист `Certificates` и папка на Диске, плюс Google запросит доступ к Диску, если его ещё не было.
2. Добавьте свойство `ADMIN_PASSWORD`, если его ещё нет. Старые свойства `BOT_TOKEN` и `OWNER_TELEGRAM_ID` больше не используются, их можно удалить.
3. Сделайте **Развернуть → Управление развёртываниями → карандаш → Новая версия**. Иначе сайт продолжит ходить в старый код. URL при этом обычно не меняется.

### Модерация отзывов

В таблице появится лист `Reviews`. Новые строки приходят с `approved = FALSE`. Чтобы отзыв показался на сайте, поставьте в этом столбце галочку / `TRUE`. Остальные столбцы лучше не переименовывать.

Антиспам на сервере:

- общий лимит: не больше 10 отзывов за минуту на весь сайт;
- плюс не чаще одного отзыва раз в 15 минут с одного и того же ключа (если отзыв оставлен из Telegram, используется идентификатор пользователя; иначе — сочетание имени и браузера).

Лимиты длины текста: от 10 до 1000 символов, оценка — только 1–5, направление — только два рабочих варианта.

Таблицу целиком публиковать не нужно. Доступен только веб-адрес скрипта, а на сайт уходят лишь одобренные отзывы.

### Как хранятся сертификаты

- Лист `Certificates` с колонками: `id`, `created_at`, `title`, `issuer`, `year`, `description`, `link`, `image_file_id`, `image_url`.
- Папку на Google Диске создаёт `setup()`. Она (и каждый файл) открыты как **«Доступны всем, у кого есть ссылка» — Просмотр**, чтобы превью работало в `<img>` на сайте.
- Для изображений в таблицу пишется публичный URL вида  
  `https://drive.google.com/thumbnail?id=FILE_ID&sz=w1600`  
  (запасной формат: `https://lh3.googleusercontent.com/d/FILE_ID=w1600`).
- PDF сохраняется на Диск, в карточке показывается заглушка, ссылка ведёт на `https://drive.google.com/file/d/FILE_ID/view`.
- Удаление сертификата (только владелец после входа) убирает строку из таблицы и отправляет файл в корзину Диска.

Перед отправкой сайт сам сжимает фото примерно до 1600 пикселей по длинной стороне (JPEG) и передаёт его как base64 в `POST` с `Content-Type: text/plain`.

## 3. Выложите страницу на GitHub Pages

1. Зарегистрируйтесь или войдите на [GitHub](https://github.com) (бесплатный аккаунт).
2. **New repository** — создайте репозиторий, например `reviews-miniapp`. Можно без README, если загружаете уже готовые файлы.
3. Загрузите в корень репозитория файлы:
   - `index.html`
   - `styles.css`
   - `app.js`
   - `config.js` (уже с URL Apps Script и вашим именем)
   - при желании `README.md`, папку `apps-script` и `tests`
4. В репозитории откройте **Settings → Pages**:
   - Source: **Deploy from a branch** (или **GitHub Actions**, если так уже настроено);
   - Branch: `main` (или `master`), папка `/ (root)`;
   - Save.
5. Через одну-две минуты адрес будет таким:  
   `https://<ваш-логин>.github.io/reviews-miniapp/`  
   (имя репозитория в конце должно совпадать).

Проверьте ссылку в браузере: должна открыться витрина. Если URL скрипта ещё не указан или одобренных отзывов нет, список будет пустым — это нормально. После подключения таблицы на витрине появятся только отзывы с `approved = TRUE`. Сертификаты, которые вы добавите после входа, появятся сразу.

## 4. Как добавить сертификат

1. Убедитесь, что выполнен раздел 2: задан `ADMIN_PASSWORD`, запускали `setup()`, веб-приложение развёрнуто, в `config.js` стоит URL скрипта, файл залит на GitHub Pages.
2. Откройте сайт в браузере (или в Telegram, если уже подключили бота).
3. Перейдите на вкладку **«Сертификаты»**.
4. Нажмите замочек в заголовке вкладки или ссылку **«Вход для владельца»** в подвале страницы.
5. Введите пароль, который сохранили в свойстве `ADMIN_PASSWORD`.
6. Нажмите **«Добавить»**, заполните название, кем выдан, год, по желанию описание и ссылку, приложите фото или PDF.
7. Нажмите **«Сохранить»**. Карточка появится на витрине сразу, без модерации.
8. Чтобы убрать карточку, нажмите **«Удалить»** на ней (кнопка видна только после входа). Чтобы выйти, нажмите **«Выйти»**.

Сессия хранится в браузере до закрытия вкладки (sessionStorage) и на сервере около 6 часов. Если вход не удаётся: проверьте, что в свойствах скрипта задан `ADMIN_PASSWORD`, выпущена новая версия развёртывания, и URL в `config.js` заканчивается на `/exec`. После нескольких неверных попыток вход временно блокируется — подождите 15 минут.

Если URL бэкенда ещё не указан, окно входа покажет подсказку, что сначала нужно подключить Google Apps Script.

## 5. Как проверить, что всё работает

1. Откройте адрес GitHub Pages в обычном браузере — витрина должна открыться и без Telegram.
2. Отправьте тестовый отзыв. В таблице появится новая строка с `approved = FALSE`.
3. Поставьте `TRUE` и обновите страницу — отзыв появится в списке.
4. Войдите как владелец и добавьте тестовый сертификат — карточка должна появиться сразу.

Отправка идёт как `POST` с `Content-Type: text/plain`, чтобы обойти CORS-preflight Apps Script. Список отзывов читается через обычный `GET`, список сертификатов — через `GET ?type=certificates`. Если браузер заблокирует запрос, фронтенд автоматически попробует JSONP. Для входа и изменения сертификатов нужен обычный JSON-ответ (без запасного no-cors), иначе нельзя получить сессионный токен.

Проверить вспомогательные функции на своей машине:

```bash
node tests/helpers.test.js
```

## 6. Если захотите открывать из Telegram

Бот не нужен для работы сайта и для добавления сертификатов. Он понадобится только чтобы витрина открывалась кнопкой внутри Telegram.

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Укажите имя (как бот будет отображаться) и username — он должен заканчиваться на `bot`, например `my_reviews_bot`.
3. Подключите страницу одним из способов (можно обоими).

### Способ А. Кнопка меню

1. В BotFather: `/mybots` → ваш бот → **Bot Settings → Menu Button**.
2. **Configure menu button**.
3. Отправьте URL GitHub Pages, например `https://username.github.io/reviews-miniapp/`.
4. Задайте подпись кнопки, например «Отзывы».

После этого в чате с ботом внизу появится кнопка, которая открывает витрину.

### Способ Б. Прямая ссылка Mini App

1. В BotFather отправьте `/newapp`.
2. Выберите бота, укажите заголовок, короткое описание, фото (квадратное, не меньше 640×640) и short name, например `reviews`.
3. В качестве Web App URL снова укажите адрес GitHub Pages.

Клиенты смогут открывать витрину по ссылке вида  
`https://t.me/<bot_username>/<short_name>`.

Дополнительно можно задать описание бота через `/setdescription` и картинку через `/setuserpic`.

Если открыть ту же ссылку из Telegram, подхватятся тема приложения и имя из профиля в форме отзыва. Вход владельца по-прежнему идёт по паролю.

## Частые вопросы

**Отзыв отправился, но на сайте его нет.**  
Он ждёт модерации. Откройте таблицу и отметьте `approved`.

**Сайт пишет, что не удалось загрузить отзывы или сертификаты.**  
Проверьте URL в `config.js` (должен заканчиваться на `/exec`), доступ веб-приложения («Все») и что после правок кода выпущены новая версия развёртывания. Затем заново залейте `config.js` на GitHub Pages.

**Изменил config.js, а на сайте старые данные.**  
Подождите минуту-две или сделайте принудительное обновление страницы. У GitHub Pages бывает короткая задержка.

**Нужно ли платить за хостинг или Google Workspace?**  
Нет. Хватит обычного Google-аккаунта и бесплатного GitHub. Не включайте платные опции Pages и не подключайте свой домен, если хотите остаться на нулевом бюджете.

**Можно ли открыть проект без Telegram?**  
Да, это основной способ. Откройте адрес GitHub Pages или `index.html` через любой статический хостинг или локально (см. ниже). Добавлять сертификаты можно прямо из браузера после входа по паролю.

**Безопасно ли хранить пароль?**  
Пароль задаётся только в свойствах Apps Script и никогда не попадает в репозиторий и в код сайта. После успешного входа сервер выдаёт случайный сессионный токен и помнит его около 6 часов. Неверный пароль сравнивается без раннего выхода по длине; после нескольких неудачных попыток вход временно блокируется.

### Локальный просмотр

```bash
cd reviews-miniapp
python3 -m http.server 8080
```

Затем откройте `http://localhost:8080` в браузере. Вкладка сертификатов: `http://localhost:8080/#certificates`.

## Приватность

В таблицу могут попасть имя, текст отзыва, оценка, направление, а также идентификатор и username Telegram, если страница открыта из Telegram (это необязательные поля). Файлы сертификатов доступны всем, у кого есть прямая ссылка на файл (так работает превью на сайте). Не делитесь таблицей на редактирование и **никогда не публикуйте пароль владельца**.
